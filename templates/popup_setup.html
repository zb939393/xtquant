📦 在 A 机器上打包 launcher.exe

把 popup_launcher.py 打成单文件 exe，并复制到 B 机器使用。

1安装 pyinstaller

python -m pip install pyinstaller

2打包 + 注册本机协议

tools\build_popup_launcher.bat

该脚本会生成 dist\popup_launcher.exe（约 18MB），并把 A 机器的 xtquant-popup:// 协议注册好（HKCU，无需管理员）。

3把 exe 拷贝到 B 机器

把 D:\xtquant\dist\popup_launcher.exe 拷贝到 B 机器任意目录（如 B 机器的 D:\C盘应用\）。

⚠ 必须在 A 机器打包的 exe 拷过去；不能用 B 机器的 Python + popup_launcher.py 替代（除非 B 机器装了完全相同的 Python + 依赖）。

🔍 A 机器本身状态自检

点下面的按钮测试：

  • 点 测试协议唤起 → 浏览器应立即失焦（进入 launcher 启动的 PyWebView 窗口）
  • 点 测试弹窗 URL 打开 → 在新标签页打开弹窗页面

🚀 三步在 B 机器启用独立弹窗

当前 {{ server_url }} 的「独立弹窗」按钮在你 B 机器浏览器点了之后没反应？ 按下面三步即可让 B 桌面弹出 PyWebView 窗口。

1从 A 机器拿 launcher.exe

让 A 机器管理员运行 tools\build_popup_launcher.bat，把生成的 dist\popup_launcher.exe 拷贝到 B 机器的任意目录（例如 D:\C盘应用\）。

⚠ 必须用 A 机器打包好的 exe（约 18 MB，含 pywebview 依赖），不要用源码 .py 替代。

2在 B 机器 cmd 注册协议

在 B 机器打开 cmd（按 Win+R → 输入 cmd → 回车），执行：

D:\C盘应用\popup_launcher.exe --register

执行后会弹一个 Windows 原生弹窗显示注册结果：

  • ✅ 成功：显示 REGISTERED · Handler: ...，关掉弹窗即可
  • ❌ 失败：显示 REGISTER FAILED ...，按弹窗里提示以管理员身份重试

如果 cmd 跑命令看不到任何输出也没弹窗，--noconsole 打包模式下 print 不可见，但会弹窗；如果连弹窗都没有，说明 exe 损坏或缺 dll，请检查 exe 版本和 B 机器是否装了 WebView2。

3验证 + 开始使用

在 B 浏览器：

  1. 访问 {{ server_url }}，Ctrl+F5 硬刷新
  2. 进入任意有「独立弹窗」按钮的页面（如 期权看板 或 期指看板）
  3. 点「🖥 独立弹窗」按钮 → B 桌面应弹出 PyWebView 窗口

本页面也提供了一键验证（看下面）。

🧪 浏览器端验证

如果不确定是否生效，可以点下面几个按钮测试。

❓ 点「测试协议唤起」没反应？
  • 按 F12 打开 Console，看是否有 scheme does not have a registered handler → 协议未注册，回到步骤 2
  • 看到 user gesture is required → 多半是浏览器策略问题，刷新页面后立即点（不要在 setTimeout 内调用）
  • 看到 window.open blocked by popup blocker → 浏览器拦截了新窗口，点击地址栏左侧的弹窗图标允许
  • 协议唤起成功但 PyWebView 窗口启动后白屏 → B 机器缺 WebView2 Runtime（下载）
  • PyWebView 窗口立刻关闭 → 看 C:\Users\<B 用户>\.xtquant\popup_launcher.log 日志最后几行

🛠 维护命令速查

注册协议
popup_launcher.exe --register
查询注册状态
popup_launcher.exe --register-status
注销协议
popup_launcher.exe --unregister
日志位置
%USERPROFILE%\.xtquant\popup_launcher.log
注册表位置
HKCU\Software\Classes\xtquant-popup

所有维护命令都会弹 Windows 原生弹窗显示结果（因为 exe 是 --noconsole 打包的 GUI 进程，cmd 里 print 看不到）。
